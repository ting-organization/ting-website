Proof of work · Programmable · Frozen since 21 October 2026

A foundation that doesn’t move

Ting is a general-purpose proof-of-work blockchain built as a permanent foundation. Its consensus is a small set of rules, written once and fixed for good: no developer, miner or foundation can change them. Coins, accounts, identities and fees are programs that anyone can deploy on top.

01Use it today

02The protocol

Consensus does four things, and nothing else

On most programmable chains, a new signature scheme, opcode, fee rule or token standard is a protocol upgrade: every node changes together, and each change can alter what existing applications do or what they cost. Ting keeps its consensus small enough to state exactly, and then leaves it alone.

  1. OneOrder

    Transactions are ordered in blocks secured by SHA-256 proof of work.

  2. TwoExecute

    Programs run deterministically in a small, exactly specified WebAssembly profile.

  3. ThreeCommit

    Every block commits to its transactions, their receipts and the resulting state.

  4. FourCount

    Four independent counters bound the compute, state access, data and storage growth of every transaction.

Accounts, signatures, coins, fees, replay protection and upgrades are not on that list. They are programs, deployed and used through ordinary transactions. What is left fits in one document:

03What it gives you

Rules that applications can depend on

Rules that stay put

The protocol was frozen at launch. Every instruction keeps its meaning and its resource charge for as long as the chain runs.

Cryptography you can replace

A new signature scheme or hash function is deployed as a program. Applications move to it when they choose, without a protocol change.

No privileged application

There is no native coin, account model or fee asset. The chain does not pick winners among the programs built on it.

Costs that don’t drift

Work is counted in logical units, not prices or nanoseconds. Faster hardware does not change what an operation costs.

Capacity without upgrades

Miners vote block capacity up or down, slowly, above floors fixed at genesis. They cannot vote to change the rules.

Room for better nodes

Implementations may compile, cache or parallelize freely, as long as every result and every counter matches.

04Agreement you can check

Nothing here asks to be taken on trust

Freezing the rules only helps if independent implementations agree on every byte and every counter. Ting is built so that agreement can be checked, not assumed.

The rules in one document

Every format, instruction, price and failure order, down to SHA-256. With a network’s seed blocks it defines the consensus completely.

Read the protocol rules

A test suite inside the chain

Every chain begins with its seed: thousands of transactions that run every instruction, host function and price step. A node that syncs has replayed the whole suite.

Conformance and testing

Two implementations

The Go node was written from the rules document alone. It validated the production seed and every later block on its first attempt.

Mine on the production network

Download the archive for your machine from the miner’s releases, check it against its SHA256SUMS and unpack it. Then, in the unpacked folder:

Ting miner
./ting init
./ting wallet create
./ting miner payout <the account it shows>
./ting miner start --threads 4
./ting start

Builds for Linux (x86-64 and ARM64), macOS (Apple silicon and Intel) and Windows, where the command is .\ting.exe. Mining is solo, and an account from Ting ID can take the payout as well. MINER.md covers the wallet, the settings and the benchmarks.

Try it on a development chain

From a checkout of the ting repository, with Rust installed, a chain of your own to run, explore and build on:

Reference node
cargo install --path node --locked
ting init --dev --api
ting start
ting mine --count 3
ting status

The node serves its own explorer at http://127.0.0.1:18441/, with the wiki at /wiki and the REST API reference at /docs. Plain ting init joins the production network instead. Next: deploy a first program.

Ting Canvas

One shared canvas a week

Anyone paints it, pixel by pixel, and every paint burns coins. When the week ends the canvas locks for good and is auctioned; the winner owns it, to name, give away or sell.

07The first coin

Daler, the first coin on Ting

Ting has no native coin. Daler (DLR) is one deployment of the reference coin program, the same program anyone can deploy with their own name, supply and rewards. The chain does not know it exists and gives it no privilege; other coins can pay miners just as well.

Daler began with nothing issued: no premine, no allocations and no account that can mint. Every coin in existence was claimed as a reward by a mined block, and a block that names no payout account issues nothing. Its deployment is on the chain for anyone to read.

08Where it stands

What to know before you rely on it

Ting is a young network and a small project. These are its weak points, stated plainly.

  1. The network is small

    Little hash power secures it so far, so someone who rents more could reorganize recent blocks. Wait for more confirmations than you would on a large network. More independent miners are what changes this.

  2. Frozen means frozen

    A flaw in the consensus cannot be patched in place. The answer to one that makes the chain unsafe is a new chain with its own genesis, which can carry the old chain’s state over. That is a coordination event, not something the protocol does by itself. Freeze consensus once

  3. Two implementations, one maintainer

    The Go node was written from the rules alone and agrees with the Rust node on every block, but both come from the same maintainer. An implementation written by someone else would be a stronger check, and is welcome.

  4. Written with AI assistance

    Much of the code was written with AI coding assistants under the maintainer’s direction. Expected results come from the written rules, never from the code under test, and the suite is part of the chain as its seed blocks. AI usage

  5. Early software

    The wallet and the miner are new. Desktop binaries are not code-signed: check each download against its SHA256SUMS and build attestation, or build from source, and keep in a wallet only what you can afford to lose.

  6. Review is the point

    The rules, the implementations, the tests and the vectors are public so that they can be checked. If something looks wrong or questionable, say so; a vulnerability goes through SECURITY.md.

09At a glance

Technical details

Consensus
Proof of work; nodes follow the heaviest valid chain
Proof of work
A single SHA-256 over Ting’s tagged block header, with a 16-byte nonce. It is not Bitcoin’s block format or double SHA-256, so Bitcoin ASICs cannot mine it and there is no merge-mining
Block time, difficulty
60-second target; difficulty moves every block on an ASERT schedule anchored at genesis, with a 12-hour half-life
Programs
A deterministic integer WebAssembly profile: 115 instructions and twelve host functions
Transactions
Two kinds: deploy and invoke
Resource accounting
Four counters: compute, state access, data and storage growth
Block capacity
Moved by miners’ work-weighted vote, slowly, above floors fixed at genesis
Coins, accounts, fees
None in the protocol: they are programs
